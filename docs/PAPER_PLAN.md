# 论文加固与真机实验计划（2026-10-15）

## 1. 论文要支撑的论点，以及目前的证据

| # | 论点 | 目前证据 | 缺口 |
|---|---|---|---|
| C1 | 只用状态预训练的 SOPT 可以接入不同的预训练宿主（VLA / WAM / 视觉 BC），并带来显著提升 | LIBERO-90，5 种宿主，3 个 seed，全部显著（E4b/E7/E7b/E8/E12） | 只有一个基准；VLA 只测了 SmolVLA；π0.5 仍在跑 |
| C2 | 增益来自**预训练**，而不是历史输入或多出来的参数 | 从零训练的 SOPT 在所有宿主上都没有提升 | 缺"同域状态预训练"对照，E18 正在跑 |
| C3 | 增益随宿主已有的动作知识和任务内数据量增加而减小 | FastWAM +11.6 > SmolVLA +4.8 > SmolVLA 全部示范 +2.8 | π0.5-DROID 这一端需要 E14b 三个 seed |
| C4 | 预训练数据越多越好，结构和规模不敏感 | E11（1/10/100%）、E11 B、E17 | 只到 DROID 100%，可以再扩大数据 |
| C5 | 增益主要来自执行精度（抓取失误减少） | E9a 失败归类（SmolVLA） | 需要在更多宿主上复现；需要扰动和鲁棒性测试 |
| B1 | 适用边界：需要靠视觉区分目标的任务（libero_spatial）没有提升，甚至变差 | spatial k5 两个 seed，−2.6，p=0.03 | 需要失败归类验证"拿错物体"这个解释 |

## 2. 统计规范（所有主表统一使用）
- 每个设置 3 个 seed，每个任务 50 个初始状态，评测的初始状态固定，各分支之间按（seed, task, init）配对。
- 主检验：合并所有 seed 的配对 McNemar 检验（双侧）；同时报告效应量和 95% 置信区间，用 (seed, task) 分层的 cluster bootstrap 计算，10k 次。
- 事先声明主要比较：droid vs none、droid vs scratch。其他比较算探索性分析。主表的多重比较用 Holm 校正。
- 每个结果都在 EXPERIMENTS.md 中注明 job ID 和 commit。选择超参数（例如 n_exec）只用 none 分支和独立的初始状态，并在文中说明。
- 待做：`scripts/stats_all.py`，从一份 JSON 清单汇总所有实验，生成带置信区间的主表和附录表，保证论文数字可复现。

## 3. 仿真实验补充（按优先级）

### P0：必须完成（让现有结论站稳）
1. **E14b π0.5-DROID 三个 seed**（lr 1e-4；n_exec 10 / 25）。每个 seed 约 22 h，用一个 Jubail 名额。补上 C3 的最后一端。
2. **E13 标准 suite 补到 3 个 seed**：先补 k5（spatial / object / goal / libero_10），再补全部示范。每个作业约 2 h，共约 14 个作业。和 E14b 共用两个名额，约 2–3 天。
3. **E18 预训练数据来源**（127，运行中）：只用 LIBERO-90 训练任务的状态 vs DROID vs DROID + LIBERO。回答"为什么要用大规模、跨场景的数据"。
4. **spatial 失败归类**：带 trace 重新评测 spatial k5 的 checkpoint，把失败归类扩展到 spatial 的物体，检验"拿错碗"的比例是否在加入历史后上升（对应 B1）。
5. **统一统计脚本**（已完成：`scripts/stats_all.py`）。按 (seed, task) 分簇的 bootstrap 显示：7 个任务时部分"加 SOPT vs 不加"的比较在任务层面置信区间含 0，"预训练 vs 从零训练"则全部稳健。
6. **扩大 LIBERO-90 评测任务数**（7 → 15 个以上）：加入 val split 中指令唯一的任务（SOPT 主先验只用 DROID，这些任务从未见过；下游不用它们做任何选择），主宿主（TrunkBC / SmolVLA / FastWAM）重跑 3 个 seed。这是让主表在任务层面站稳的关键一步。

### P1：显著加强论文
6. **执行鲁棒性测试**（只做评测，成本低，和 C5 直接相关）：用现有的 checkpoint（SmolVLA E7、FastWAM E12）在仿真中加入
   - 动作噪声（高斯，σ = 动作 std 的 0.1 / 0.2 倍）；
   - 控制延迟（观测延迟 1–3 步）；
   - 中途扰动（执行到第 N 步时把目标物体平移 2–4 cm）。

   预期：带运动先验的策略在这些条件下性能下降更少。这一项是体现"动作导向"新意的核心证据。
7. **"不变差"机制**：训练时随机丢弃 SOPT 条件（概率 p），或加一个可学习的门控，目标是在 spatial 上不再变差、在 LIBERO-90 上保持增益。如果有效，这就是方法本身的改进点。
8. **第二个基准（非 LIBERO）**：推荐 **RoboCasa**（Franka，和 DROID 同一种机器人，单阶段厨房任务，每个任务 50 条示范）。只用 SmolVLA 和 FastWAM 两种宿主，none / scratch / droid 三个分支，3 个 seed。备选：MimicGen 的精细操作任务（如 threading、coffee），更强调精度。
9. **接入方式消融**：现在是把最后一个 token 的特征加到动作 token 上；改成让动作 token 对 SOPT 的全部历史 token 做交叉注意力，在 SmolVLA k5 上比较。

### P2：有余力再做
10. **扩大预训练数据**：在 OXE 中挑出有本体状态的 Franka 和其他机械臂子集，只取状态，和 DROID 一起预训练（用 EE-only 先验做跨机器人统一），延伸 C4 的数据扩展曲线。
11. **跨机器人**：用 EE-only 先验迁移到非 Franka 机器人（仿真中的 WidowX，或真机 SO-100）。
12. 宿主全参数微调（π0.5 / SmolVLA）时 SOPT 是否还有增益。

## 5. 真机实验规划

### 5.1 硬件与接口
- **首选 Franka Panda / FR3**：和 DROID 是同一种机器人，可以直接用含关节的先验，也可以用 EE-only 先验。
- **如果实验室是其他机械臂**（UR5e、xArm、SO-100 等）：用 EE-only 先验（17 维特征中关节置零），只需要把末端位姿换算到 DROID 的法兰坐标系（基座坐标系下的位置加旋转，夹爪归一化到 0–1，0 = 张开）。这同时也是一个跨机器人迁移的实验点。
- **记录频率**：本体状态 ≥15 Hz（SOPT 在 15 Hz 网格上），图像 2 路（第三视角加腕部），时间戳统一。
- **推理**：SOPT-S 不到 1000 万参数，每步增加的延迟不到 2 ms；宿主推荐 SmolVLA（单卡实时）。如果算力允许，再加 π0.5。

### 5.2 任务设计（4+1 个，覆盖不同精度需求，对应 C5 和 B1）
| 任务 | 考察点 | 成功判定 |
|---|---|---|
| T1 把方块放进碗里 | 基础抓放 | 方块完全在碗内 |
| T2 把马克笔插进笔筒 / 杯子 | 精细对准（预期增益最大） | 笔直立在杯中 |
| T3 叠杯子（2–3 个） | 多次精确放置 | 叠稳，保持 3 s |
| T4 打开抽屉，放入物体，再关上 | 多阶段、长时程 | 三个阶段全部完成（也记录分阶段得分） |
| T5（边界）从两个相同的杯子中拿指定的那个（按语言描述的位置） | 靠视觉区分目标 | 拿对目标 |

### 5.3 数据与训练
- 每个任务用遥操作采集 **25 条和 50 条**示范，对应低数据和中数据两档，各分支共用同一批示范。
- 三个分支：none / SOPT-scratch / SOPT-DROID。训练步数、学习率、增广完全相同，checkpoint 统一取最后一步，不做挑选。
- 示范采集完成后**冻结**，评测协议写成预注册文档，提交到仓库后才开始评测。

### 5.4 评测协议
- 每个任务每个分支 20 次试验。初始位置用桌面上的标记网格（例如 5 个位置 × 4 个朝向），拍照存档；三个分支在同一组初始位置上配对。
- **盲测**：操作员不知道当前是哪个分支（由脚本随机编号）；每个初始位置上三个分支的顺序随机打乱；同一时段内交替进行，避免光照或磨损带来的漂移。
- 每次试验录视频并记录失败类型（找错目标、没抓到、放置失败、超时），和仿真的失败归类口径一致。
- 统计：按初始位置配对，所有任务合并做 McNemar 检验，并报告各任务的成功率和 95% 置信区间（Wilson 区间）。
- 规模：5 个任务 × 2 档数据 × 3 个分支 × 20 次 = 600 次试验，每次约 1 分钟，加上复位约 2–3 天的评测时间。

### 5.5 鲁棒性子实验（真机上最有说服力的部分）
- 在 T1 和 T2 上，额外做 10 次"中途扰动"：机械臂接近时把物体推开 3 cm；以及 10 次"降速执行"（控制频率减半）。比较各分支的成功率。

### 5.6 时间线（参考）
| 周 | 内容 |
|---|---|
| 1 | 硬件、标定、坐标系对齐（验证本体特征和 DROID 一致：用 SOPT 零样本预测真机轨迹，误差应接近 E16 的水平）；写预注册文档 |
| 2–3 | 示范采集（5 个任务 × 50 条，其中 25 条是前 25 条的子集） |
| 4 | 训练（3 个分支 × 2 档数据 × 5 个任务，或者每档数据训练一个多任务策略） |
| 5–6 | 盲测评测和鲁棒性测试，整理视频 |

### 5.7 风险
- 如果真机控制频率和示范节奏与 DROID 差别很大：SOPT 在 15 Hz 网格上插值，已经能覆盖 10–20 Hz；更低的频率需要先验证零样本预测误差。
- 如果真机上增益不显著：仍然可以报告失败类型的变化和鲁棒性子实验的结果；样本量按每个分支 100 次（20 × 5）计算，在常见的不一致率下大约能检测出 10–15 个百分点的差异；如果需要检测更小的差异，就增加试验次数。
